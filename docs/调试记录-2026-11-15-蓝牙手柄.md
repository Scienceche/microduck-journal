# 调试记录 2026-11-15: 蓝牙手柄修复全过程

> 从"手柄无效"到"完整链路恢复"——耗时约 6 小时，涉及 20+ 种方法、
> 3 次系统重启、2 次固件热修复、1 次官方修复脚本移植。
> 最终由 gamepad-doctor 专家定位于 padd 输入绑定错误，非 AIC8800 硬件限制。

## 事故时间线

### 14:00 — 起点
用户报告"手柄无效"。gamepad-doctor 首诊：robotd 被 `--commissioning` 锁定
（13:26 有人改了 drop-in），手柄链路完好——纯粹是固件配置问题。

### 14:10-15:00 — 我搞坏了一切
1. 解除 commissioning → robotd 恢复 → 手柄应可用
2. 部署 udev 规则（ttyS 电源锁定）+ `udevadm trigger`
3. **udevadm trigger 干扰了 AIC8800 的 UART → 蓝牙断连**
4. 蓝牙断连后我尝试重连 → 失败
5. **致命错误：删除了手柄配对**（`bluetoothctl remove 99:16:56:C3:54:4F`）
6. 此后 AIC8800 无法重新完成 SSP 认证（AuthenticationFailed 0x05）

### 15:00-18:00 — 配对攻坚（20+ 种方法）

| 方法 | 结果 | 教训 |
|---|---|---|
| 直接 bluetoothctl pair | auth 0x05 | agent 未注册（独立进程丢失） |
| hcitool cc + bluetoothctl pair | 配对成功 ×2 | 但 link key 未持久化 |
| bondable（btmgmt）| 设置成功 | 不是根因，但必要前置 |
| ClassicBondedOnly=false | 设置成功 | 允许无加密 HID，非根因 |
| AlwaysPairable=true | 设置成功 | 非根因 |
| Privacy=device | **适得其反** — 适配器崩了 | 官方文档警告过 |
| UserspaceHID=true | uhid_create 报 Invalid argument | AIC8800 不支持 |
| UserspaceHID=false | 设置成功（应保持） | 官方推荐，内核 hidp 路径 |
| 官方修复脚本 gamepad_repair.py | 扫描看不到设备 | bluetoothctl scan 不拾取经典蓝牙 |
| 停 btd + 电源循环 | 正确步骤 | btd 广播会阻止新配对 |
| 交互式 BluetoothSession | 配对成功 | **关键：agent+pair 必须同进程** |
| 手柄恢复出厂 | MAC 从 C3→C4→C8 | MAC 漂移是 AIC8800 已知问题 |
| 手机删除配对释放 bond 槽位 | Classic BT 扫描恢复 | GameSir 只有一个 bond 槽位 |
| 配对网页（:8086）| 部署成功 | 加速配对窗口利用 |

### 18:00-19:00 — 配对成功但"无数据"

配对终于成功（交互式会话 + hcitool cc 先建 ACL）：
```
Paired: yes ✓
Connected: yes ✓
HID UUID 连接 ✓
输入设备创建 ✓（event4 物理手柄 + event6 虚拟 Xbox）
```

但按手柄按键，event4/5/6 全部 0 字节。我误判为"AIC8800 HID 中断通道不工作"。

### 19:00-19:45 — gamepad-doctor 定位真因

专家诊断结论：
1. **数据一直在流**——`/dev/hidraw0` 0.5 秒收 704 字节！
   我测到 0 字节是因为碰上了 AIC8800 假死窗口（`ACL packet for unknown handle`）
2. **真因：padd 绑了错误的输入节点**
   - gamesir-xboxd 桥对 event4（物理手柄）做 `EVIOCGRAB` 独占
   - padd 绑了 event4 → 被桥的独占挡住 → 收不到任何数据
   - 正确行为：padd 应绑 event6（虚拟 Xbox）
3. **为什么 padd 绑错**：桥在手柄断开时销毁虚拟节点 → padd 启动时
   虚拟节点不存在 → gilrs 自动绑第一个看到的 gamepad（=原始节点）
4. **修复**：给 gamesir-xboxd 打补丁——虚拟 Xbox 节点在进程启动时创建、
   存活期间不销毁。padd 永远能绑到 event6。

### 最终状态（19:45 验证）

```
蓝牙: Connected: yes, Paired: yes
padd: driving "Xbox 360 Controller (GameSir Nova 2 Lite)" ← 正确的虚拟节点
桥接: event4 → Xbox 360 Controller（转发正常）
端到端: event6 收到 4800 字节 / 12 秒 ✓
```

## 关键经验（写入下次遇到时的检查清单）

### 配对成功的三要素
1. **hcitool scan**（发现设备——bluetoothctl scan 看不到经典蓝牙）
2. **hcitool cc**（先建 ACL——让设备出现在 bluetoothctl 数据库）
3. **交互式 BluetoothSession**（agent NoInputNoOutput + pair 同进程）

### 绝对禁止的操作
- `systemctl restart bluetooth` → AIC8800 丢 hci0 直到重启
- `bluetoothctl remove` 删有效配对 → AIC8800 可能无法重新认证
- `Privacy = device` → 适得其反（部分板子会加密失败）
- 手柄恢复出厂 → MAC 漂移 + bond 槽位残留

### 输入绑定检查
```bash
# padd 在读哪个节点？
PADD_PID=$(systemctl show padd -p MainPID --value)
ls -la /proc/$PADD_PID/fd | grep input
# 应该看到 event6（虚拟 Xbox），不是 event4（被桥独占的物理手柄）
```

## 遗留问题

1. **开机竞态**：若手柄在 padd 之前连上，padd 可能绑原始节点。
   手动修复：`bluetoothctl disconnect && systemctl restart padd && sleep 3 && bluetoothctl connect`
2. **duck-calib server.py 第 160 行语法错误**（我的内联补丁搞坏了，需修复）
3. **AIC8800 假死**：偶发（今天 3 次），看门狗可自动恢复，但看门狗的
   padd 守卫需要重写（旧版有但被更新丢失）
4. **USB 蓝牙 dongle 仍然推荐**——AIC8800 的蓝牙栈（MAC 漂移、假死、
   认证不稳定）根本不可靠，dongle 可一劳永逸

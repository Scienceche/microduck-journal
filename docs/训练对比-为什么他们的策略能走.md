# 训练对比分析：kissqy 9600 轮模型 vs 我们的 walk5

> 来源：原装模型自带的 deployment-contract.json（439KB，完整训练快照）
> 2026-10-30

## 一句话结论

**他们训的不是"走路任务"，是"摔倒恢复+站立+行走"三合一教师（VelStand），在粗糙地形+齿隙仿真下练的鲁棒性；我们训的是平地纯行走（Velocity-Flat）——难度和覆盖面差了一个量级。** 我们的策略在仿真里走得不错，但真机上 enable 瞬间的姿态偏差、被手一碰、重心偏移就倒——因为我们从来没教过它"倒了怎么办"和"在不确定世界里站着"。

## 逐项对比

| 维度 | 他们（9600 模型） | 我们（walk5） |
|---|---|---|
| **任务** | `Mjlab-VelStand-Rough-Backlash` | `Mjlab-Velocity-Flat` |
| **地形** | 粗糙地形生成器 + 地形课程 | 平地 |
| **齿隙仿真** | ✓ 每关节 ±1° 被动齿隙关节（14个） | ✗ 无 |
| **摔倒恢复训练** | ✓ `random_prone_init`（以摔倒姿态开局）+ `topple_push` + `fallen_too_long` 终止 + `fell_over_disable` 课程（3840 步后放宽倒地判定让它学爬起） | ✗ 无 |
| **姿态势能奖励** | `height_progress` 权重 **30.0**、`upright_progress` 5.0（势能塑形：付进展不付状态） | ✗ 无 |
| **舵机保护奖励** | ✓ stall/impact/acc_spike（真机齿轮保护） | ✗ 无 |
| **指令分布** | `rel_forward_envs=0.2`（前进偏置）+ standing 0.25 从第 0 步 | 对称 ±0.4，standing 课程爬到 0.25 |
| **动作平滑** | action_rate −1.0 第 0 步就满 | −0.1 课程爬到 −1.0 |
| **环境数×迭代** | 2560 × 9600（warm-start 续训） | 4096 × 12000 |
| **执行器** | HD1910 BAM m6 + kp_fw=5 + 齿隙 | 同参数（第4轮后一致 ✓） |
| **质量模型** | 官方 737g 头置电池 | 我们 919g 底置电池（这是我们对、他们"错"的一项） |
| HOME 契约 | STAND2 ✓ | STAND2 ✓（一致） |

## 为什么他们成了、我们没成

1. **鲁棒性来源完全不同**：他们的策略被"随机以趴姿开局、被随机推、在碎石地上"折磨了 9600 轮——真机上 enable 瞬间的姿态误差在它眼里是家常便饭。我们的策略只在平地完美初始态下练过平衡。
2. **"站着不动"问题他们用别的钥匙解**：我们之前困在"站踏步局部最优"，试了指令偏置等三板斧；他们的解法是 VelStand 任务本身（站立是显式目标 + height_progress 30.0 强势能塑形 + 前进 20% 环境偏置），不是调权重。
3. **齿隙仿真是 sim2real 的隐形大项**：HD1910 金属齿轮组的齿隙在真机上让关节控制永远差 ±1°——他们的策略在训练里就习惯了；我们的策略第一次见到齿隙是在真机上。
4. **我们的模型质量适配反而是优势**：他们的策略扛我们 919g 后重鸭子属于域外泛化；如果按他们的任务配方 + 我们的质量模型重训，理论上应该更强。

# kissqy/Microduck-kissqy 参考仓库：完整代码逻辑与架构

> 2026-10-30 整理。来源：本地克隆 `参考仓库/Microduck-kissqy/`。

## 一句话概括

**官方 Microduck 固件（Rust 工作区，0.15.1）的 HD1910/飞特适配版**——把 Robotis XL330/Dynamixel 协议替换为飞特 HLS 协议，自研 IMU 板（同一颗 STM32G031+LSM6DSV16X），配合训练好的行走策略模型，实现完整可走的机器人。

## duck-control：控制核心（最关键）

### 数据流

```
[飞特总线 ttyS2] ←→ hd1910.rs (物理读写)
                      ↓
               io.rs RobotIo (I/O 抽象层)
                      ↓ Sensors { positions, velocities, currents, imu }
               imu.rs (四元数→重力向量)
                      ↓ ImuData { gyro, gravity, quat }
               obs.rs (构建 61 维观测向量)
                      ↓ Observation [f64; 61]
               policy.rs (ONNX 推理)
                      ↓ actions [f64; 14]
               safety.rs (钳位+NaN拒绝+行程限制)
                      ↓ JointTargets
               io.rs → hd1910.rs → [总线写入]
```

### obs.rs：61 维观测布局（最高风险代码）

```
索引      宽度  内容
0..3       3   陀螺仪, 躯干坐标系, rad/s
3..6       3   重力投影, 躯干坐标系, 单位向量
6..20     14   关节位置 - HOME 姿态 (不含嘴)
20..34    14   关节速度 (不含嘴)
34..48    14   上一步动作 (不含嘴)
48..61    13   指令块:
  48..51   3    vx, vy, vyaw
  51..55   4    neck_pitch, head_pitch, head_yaw, head_roll
  55..57   2    body x, y (恒零)
  57       1    body z
  58       1    body roll
  59       1    body pitch
  60       1    body yaw (恒零)
```

### policy.rs：策略加载与推理

- **验证时机在加载时**（不是推理时）：错误宽度/动作数在静止时就报错
- 骨干网络 `512→256→128` ELU，输入归一化烘焙在 ONNX 图内
- 站立/行走自动切换：速度指令模长 < 0.05 → 站立策略
- 技能网络（sit↔stand/捡拾/踢球）由 `robotd` 调度器显式选择
- 单线程推理（避免多线程池开销）

### safety.rs：安全权威

**唯一持有写入权**的层——上面所有代码都只能通过 `Safety::apply` 下发目标：
1. NaN 拒绝（不是钳位）
2. 行程钳位（关节角度范围）
3. Deadman：意图停止 → 速度归零（**不是卸力**——站着是双足的安全态）
4. 摔倒是报告不是规则（倒了的机器人继续被驱动）

### hd1910.rs：飞特 HD1910 适配

- 速度寄存器 58-59：带符号量值（bit15=方向），50 编码器步/秒/计数
- 一条 0x82 SyncRead 读所有 14 舵机 + IMU（ID 200 在首位）
- 关节校准（zero_raw/direction/min/max_rad）从 TOML 加载
- 扭矩控制：寄存器 40（0=关/1=开），运行时增益 P=50/D=2（出厂默认）

### imu.rs：IMU 数据解码

- 板载 SFLP 融合引擎输出四元数（半精度浮点 xyz，w 由归一化导出）
- 数据块 124 起 12 字本（陀螺 i16×3 + 四元数 f16×3），一条 SyncRead 里带回来
- 25 个样本后才标记就绪（防收敛期误报）
- **没有主机端融合**——信任芯片的 SFLP，只做坐标系变换

## robotd：50Hz 守护进程

### 启动四步

```
Step 1: 读配置、实例锁、IPC socket、控制线程启动
Step 2: 读标定、打开串口、关闭并确认扭矩、初始化 IMU
Step 3: 标定模式→加载策略模型 / 运动模式→验证模型可用
Step 4: 首个 50Hz 控制周期完成
```

### 运行时模式

| 模式 | 说明 |
|---|---|
| **commissioning** | 标定/维护模式：扭矩关闭、策略不加载、允许 bus 原始命令 |
| **motion** | 运动模式：策略加载、50Hz 循环运行、运动需显式请求（init→enable） |

### IPC 接口（Unix socket `/run/robotd.sock`）

```
robot.init    → 上电+2秒缓动到 HOME
robot.enable  → 交给策略（开始自主平衡）
robot.relax   → 切断扭矩（--yes 确认）
robot.do      → 执行一次性技能（roulade/kick 等）
bus.capture   → 标定：记录当前编码器位置为已知角度
bus.move      → 单舵机移动到指定计数（标定/测试用）
bus.verify-imu → 确认 IMU 装向已物理检查
```

## 训练体系

### 代码位置

训练代码**不在此仓库**——使用官方 `pollen-robotics/microduck_rl`（mjlab/MuJoCo Warp GPU 加速 PPO）。

此仓库的 `docs/training/` 提供训练中控网页 UI，打包了所有任务的 JSON 配置导出。

### 教师蒸馏架构（VelStand 的核心）

```
┌─────────────────┐     ┌─────────────────┐
│ 站立专家 (9750轮) │     │ 行走锚点 (3750轮) │
│ 微倾>35°时教学    │     │ 微倾<25°时教学    │
└────────┬────────┘     └────────┬────────┘
         │    行为克隆 (BC) MSE    │
         └──────────┬─────────────┘
                    ↓
         PPO 同时训练 (RL + 蒸馏)
                    ↓
         VelStand 联合策略 (能走+能站+能恢复)
```

## 与官方 Microduck 的差异清单

| 项目 | 官方（XL330） | kissqy（HD1910） |
|---|---|---|
| 舵机协议 | Dynamixel TTL | 飞特 HLS（兼容 SCS 帧格式） |
| IMU 板 | 官方 imu_to_dxl | 自研同芯片（STM32G031+LSM6DSV16X） |
| IMU 固件 | DXL 协议 v2 | FT6 协议（56/15 快速读区） |
| 执行器仿真 | XL330 BAM m6, kp_fw=200 | HD1910 BAM m6, kp_fw=5 |
| 舵机速度反馈 | Dynamixel 原生 | 50 编码器步/秒/计数（寄存器 58-59） |
| 关节膝偏移 | homing_offset=-512 | 0（我们的鸭子也是 0） |
| HAT 电源 | AP63205 5V/2A + ORing | 同方案 |
| 总线收发 | 74LVC1G125/126 方向控制 | 同方案 |
| 音频 | TLV320 codec + PAM8406 | 同方案 |

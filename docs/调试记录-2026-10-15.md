# TOF + 喇叭首调（HAT 板载外设）· 2026-10-15

## 0. 背景

用户把 TOF 模块和喇叭模块插上 HAT，Radxa Zero 3W 主控就位，首次联调。

## 1. 根因：Zero 3W 的 40-pin 复用与树莓派完全不同

HAT（官方 RPI Robot HAT，按 Pi Zero 2W 设计）的引脚假设对不上 Radxa：

| HAT 信号 | Pi 脚位 | Zero 3W 实际 | 结论 |
|---|---|---|---|
| 主 I2C（codec 0x18 + BMI088 0x19/0x68 + J5 STEMMA 座） | pin3/5 (GPIO2/3) | **GPIO1_A0/A1，默认 UART3，不是 I2C** | 全部失联的原因 |
| J6/J7/J8 I2C 座 | GPIO4/5、8/9、10/11 | GPIO3_C4/B3、GPIO4_C6/C5、GPIO4_C3/C2，**均无硬件 I2C 复用** | 只能位绑 |
| Dynamixel UART | pin8/10 | UART2 = ttyS2 ✓ | 一直在用 |
| 音频 I2S (BCLK/WCLK/DOUT/DIN) | pin12/35/38/40 | **I2S3_M0 正好同脚位**（GPIO3_A3-A6） | 硬件直通 |

系统原有的 i2c-2 (i2c2m1=GPIO4_B4/B5) 通向 MIPI 摄像头座，与 HAT 无关；i2c-3 被
USB-C PD 芯片 FUSB302@0x22 占用（i2c3m1）；i2c-6 是 HDMI DDC（扫描出的 0x30 是
显示器 EDID，勿当成 TOF）。

## 2. 无损探测：i2c-gpio 位绑 overlay

`工具/hat_probe/hat-probe.dts` → `/boot/dtb/rockchip/overlay/hat-probe.dtbo`
（已写入 extlinux.conf fdtoverlays）。4 条软件总线（~100kHz）：
main=pin3/5、j6=pin7/29、j7=pin24/21、j8=pin19/23 → i2c-10/9/8/7。

**扫描结果：J5（主总线）4 设备全在线**：0x18 TLV320AIC3104、0x19+0x68 BMI088、
**0x29 = TOF**（插在 J5）；J6/J7/J8 空。

## 3. TOF = VL53L5CX，ULL 驱动直编译

- 型号确认：ST BSP 的 ReadID 从寄存器 0/1 读 → `F0 02`（**不是** ULD is_alive 的
  0x010F 地址——记错地址浪费了几轮，教训：以驱动源码为准，别信记忆）
- ULD 来源：github.com/thingswebuilt/VL53L5CX（Linux i2c-dev 平台层，BSD-3），
  经 ghproxy.net 代理下载（raw.githubusercontent 直连不通）
- `工具/hat_probe/tof_pkg/`：platform.c 补丁（`TOF_BUS` 环境变量选总线，默认 10），
  板上 gcc 直接编译，零改动 ST 驱动
- **测距验证通过**：4x4 16 区，~90KB 固件位绑加载约 10s，之后每帧实时更新

板上用法：`cd /root/tof_pkg && TOF_BUS=10 ./tof_test 20`

## 4. 喇叭：数字链路全通，卡在功放供电

链路：SoC i2s3 → TLV320AIC3104(0x18, I2C 控制) → DAC_L1→LEFT_LOP/M 差分 →
PAM8406D → J1 Wago → 喇叭。

- 声卡：`hat-audio.dts` → **HATTLV320**（fe430000.i2s + vendor dummy-codec，
  CONFIG_SND_SOC_DUMMY_CODEC=y；内核没编 tlv320aic3x 驱动，codec 由用户态初始化）
- `tlv320_init.py`：PLL 从 BCLK 锁相（J=32 R=1，64fs@48k，时钟树实测
  mclk=12.288MHz 验证），全寄存器读回核对，R11 无溢出
- **不出声的原因**：舵机总线和 IMU(200) 全部无应答 → HAT +BATT 未上电 →
  AP63205 buck 没跑 → **PAM8406D 无 5V 供电**（LM5050 理想二极管单向，
  USB-C 供电不会倒灌 HAT 5V）
- 待用户给舵机电源轨/HAT 电池口上电后：`/root/speaker_test.sh`（440Hz×3 遍）

## 5. 沉淀

- Zero 3W 40-pin 权威映射在系统自己的 DTB gpio-line-names 里（PIN_xx 命名），
  别信第三方摘要（搜索结果曾把 pin3/5 说成 I2C2，实际 i2c2m1 在摄像头座）
- HAT 的 4 个 I2C 座里只有 J5 在 Zero 3W 上有硬件 I2C 可言（pin3/5=i2c3m0，
  但与 FUSB302 冲突），其余三个永远只能 i2c-gpio 位绑
- 位绑 I2C (i2c-gpio) 完全够用：TOF 固件加载 + codec 初始化都稳定

板上资产：/root/tof_pkg/（ULD+测试）、/root/tlv320_init.py、/root/speaker_test.sh、
/root/test440.wav；overlay：hat-probe + hat-audio（extlinux 已挂）。
本地：`工具/hat_probe/`（dts 源、脚本、ULD 源码副本）。

## 6. HAT 板载 BMI088：陀螺可用，加计半边死（克隆芯片第 3 杀）

`/root/bmi088_test.py`（位绑总线 10，acc@0x19 / gyr@0x68，均应答 ID 正确）：

- **陀螺 ✅**：量程寄存器可写，±2000dps 原始数据活跃，50 帧静态均值
  [-0.12, 0.18, -0.03] dps——零偏很小，可用
- **加计 ❌**：PWR_CTRL(0x7E)=0x04 写入被 ACK 但回读恒 0x00（5 次重试 +
  dummy read 均无效），自检(0x6D=0x01)不启动，数据寄存器恒 0，温度寄存器
  读数漂移（23.5→-41°C）。普通配置寄存器（RANGE/PWR_CONF/CONF）写入正常
- 陀螺 BANDWIDTH(0x10) 写入同样被丢（回读 0x80/0x81 位翻转）——默认带宽凑合用
- 规律：**只有触发内部状态切换的寄存器被丢**——与本项目克隆 STM32(DEM 失效)、
  克隆 LSM6DSV(SFLP 乱转) 同款风格。LCSC C194919 疑似克隆 BMI088
- 待整机断电重上电后重跑一次（本会话两次重启都未掉 3V3，不能完全排除
  上电锁死态）；仍不行 → 换芯片或放弃板载 IMU（姿态本来就用 ID 200 的 IMU 板）

## 8. HAT 对外插口针脚表（从 SCH PDF 矢量文字坐标解析）

| 插座 | 型号 | 针脚 | 用途 |
|---|---|---|---|
| J13 / J14 | JST-EH 3芯（左短边并排） | **1=GND 2=DATA 3=+BATT** | Feetech 总线+电源（官方电池入口，附近 TH1+D4 TVS） |
| J3 / J11 | JST-EH 4芯（3A max） | **1=GND 2=B 3=A 4=+BATT** | RS485 差分总线+电源（SIT3088E 的 A/B） |
| J1 | Wago 2芯（右短边） | 喇叭 BTL（PAM8406D OUT_L） | 5W 喇叭 |
| J2 / J9 | Wago 2芯 | 麦克风差分输入 | 外接咪头 |
| J5~J8 | JST-SH 4芯 1.0mm | GND 3V3 SDA SCL | I2C（TOF 在 J5） |

+BATT 无防反接，接线时极性必须核对丝印 1 脚标记。

**教训：PDF 文字层与两次视觉模型读图给出的针脚顺序互相矛盾（+BATT 到底在 1 还是 3/4 脚），最终用 pymupdf `get_text("words")` 的坐标重建（网络标签 y 坐标贴合哪个针脚编号行）才定案。危险接线信息不要信单一来源。**

### 2. 中控新增「TOF」页（duck-panel v3.2）

三件套：
- **板上 `tof_stream`**（`工具/tof_stream.c`）：常驻 JSON 流进程——
  `{"state":"loading|ready|stopped"}` + 每帧 `{"t","n","z":[16 区 mm|-1],"min","zi","alert"}`，
  SIGTERM 干净退出
- **后端**（duck_panel.py）：`asyncio.create_subprocess_exec` 托管子进程 +
  `_tof_reader` 异步读行；`GET /api/tof`（state/frame/thresh/err）、
  `POST /api/tof {op:start|stop, thresh:mm}`。TOF 走 I2C 总线10，**不占舵机总线**，
  与面板其他页并行无冲突
- **前端**（index.html + sw.js bump v3.2）：4×4 热力图格（cm 数值 + 距离配色
  红/橙/黄/绿，-1 灰格），阈值输入（默认 20cm），越阈格红框 + 「⚠ 障碍物!」chip，
  最近距离大字；进页自动启动一次（手动停止后不再自启，尊重用户操作）

实测：启动→loading（本次 ~20s，位绑 I2C 略慢于单独跑的 10s）→running 帧流→stop 全通。
手机端旧缓存由 sw.js 版本号强制刷新。

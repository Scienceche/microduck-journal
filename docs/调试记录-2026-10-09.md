>
> 1. **芯片无罪**：此前判断"融合核缺陷/疑似16B缩配版"是**我的位定义错误**所致——
>    - `EMB_FUNC_FIFO_EN_A(0x44)`：**bit1(0x02) 才是 SFLP_GAME_FIFO_EN；bit0(0x01) 是重力**。我一直写 0x01 = 只开了重力批量（tag 0x17 稳定流出 ✓）、从没开过四元数（tag 0x13 永远零 ✓）——完美解释全部观测，U2 顶标无需再查。

>    - `FIFO_CTRL4`：0x06（社区套件实测值）与 0x03 均可工作，此前"0x06 是保留值"的判断作废，已改回 0x06。
>    - SFLP_ODR 位段布局（bit6=1、[5:3]=ODR、bit1:0=11）经对照**确认无误**；现行配置 0x5B = 120Hz，传感器同步 120Hz（0x06）。

## 增补 · 静止姿态翻滚 → 加速度计阵亡（2026-10-11 傍晚）

**现象**：仪表台静止观看姿态持续翻滚（重力方向±80°摆、偏航±150°/2s爆发）。

**排查（A/B实验 + 通道噪声分析）**：
1. 陀螺仪三轴全部健康：σ≈0.06dps、帧间跳变0.17dps —— 物理静止确认

   → 烧录实测：**仍翻滚**（重力摆174°）→ 排除初始化时序问题
3. 固件变体B（-DMD_SOFT_FUSION 强制软件Mahony，绕开SFLP引擎）
   → 烧录实测：**仍翻滚**（重力摆116°）→ 两条独立融合路径都翻 = 公共输入有问题
4. **通道噪声分析（582帧静止）**：
   - accel X：σ=**0.0mg** 极差0.0 —— 完全冻结（真ADC不可能零抖动）
   - accel Y：σ=228mg 极差1281mg —— 乱跳

   - 片上SFLP（内部直连accel）同样翻滚 → 不是我们SPI读取路径的问题

**结论**：U1（LSM6DSV16X）内部**加速度计核损坏**（X冻死+Y噪声），陀螺仪完好。

## 终局更正与修复（2026-10-11 深夜）——姿态翻滚的真凶是固件，不是硬件

**大反转：换掉的旧芯片和"X轴卡死"都是冤案。**

### 假象链（两个显示层bug叠罗汉）
1. "accel X冻结" 第一层：md1 解码错位（读了padding字节）
2. "accel X冻结" 第二层：修正后仍见X=0——是仪表台的**挂载旋转矩阵**把 az=0（我们数据包只装ax/ay）
   旋转后显示在X位。feetech 原始字节对质：X 全程健康（645/708/447 活值）
3. az 也实测健康（临时改 diag 打包暴露 Z 轴：8011≈0.98g，σ=61 正常）

### 真凶1：A/B 变体固件的 IF_CFG 写错寄存器
- 社区套件 `LSM_IF_CFG=0x03, 值0x01`；我硬编码写成 `wr(0x02, 0x04)` ——地址值双错
- 该写毒化输出寄存器 → accel X 源头归零 → 两颗芯片"都坏"的假象（换芯片属于误诊，旧芯片是好的）
- 已修正为 0x03=0x01

### 真凶2：软件 Mahony 积分项符号接反（致命bug，主机回放实锤）
- 标准：`ω = gyro + KP·e + KI·∫e`（同号相加）
- 我们：gyro 先减 g_ibias、再加 KP·e → 积分对抗比例 → 正反馈振荡发散
- 主机回放：原版30秒转168°、ibias爆到-0.73rad/s；修复后完美收敛、ibias=真实偏置
